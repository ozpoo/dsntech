Project 01: The Task Journey

Information Architecture & Interactive Wireframing

Canvas Assignment Settings:

  • Points: 200
  • Submission Type: Online
    Website URL / Figma Link + File Upload
  • Allowed File Types: .pdf (for Journey Map/IA)

Project Overview

Design Technology II moves us from designing artifacts to designing behaviors. Before we build interactive, high-fidelity design systems, we must understand how users navigate information to accomplish tasks.

For this project, introduced in Tuesday Lecture and engineered during Thursday Labs, you will act as an Interaction Designer tasked with restructuring a complex digital process. You will strip away visual styling (colors, typography, images) to focus purely on Information Architecture (IA), user flows, and structural wireframes.

Pillars Addressed: Cognition, Research, Systems

Course Outcomes: Map user journeys, analyze tasks, and utilize prototyping environments (Figma) to design structural wireframes.

Learning Objectives

By the end of this project, you will be able to:

  1. Conduct task analysis to break down a complex user goal into actionable steps.
  2. Map a User Journey that anticipates friction points and user contexts.
  3. Develop an Information Architecture (IA) map.
  4. Translate cognitive structure into low-fidelity, screen-based wireframes.

Lecture vs. Lab Execution Schedule

  • TUE Lecture Briefing: Usability heuristic theory, task analysis methodologies, friction point identification, grayscale constraint rules, and cognitive hierarchy.
  • THU Lab Execution: Guided user journey mapping in FigJam, information architecture diagramming, Figma frame setup, and peer usability testing of wireframe flows.

Step-by-Step Instructions

The Scenario

Choose one of the following notoriously complex digital tasks to restructure and improve:

  • Option A: Registering for classes on a university portal.
  • Option B: Booking a multi-city train or flight itinerary.
  • Option C: Checking out at an online grocery store with dietary-restricted substitutions.

Part 1: Task Analysis & User Journey

(Lecture Theory / Lab Mapping)

Break down the user's goal. Document their starting point, the steps they must take, the decisions they must make, and their endpoint. Map this out visually (using FigJam, Miro, or Illustrator) to show the "happy path" and potential points of friction.

Part 2: Information Architecture (IA)

(Lab Execution)

Create a site map / flow diagram showing the hierarchy of screens and information the user will encounter. How are the menus organized? What information lives on which screen?

Part 3: Low-Fidelity Wireframes

(Lab Execution)

Using Figma, translate your IA into low-fidelity structural wireframes.

  • Constraints: Use only shades of gray, one standard sans-serif font (Inter or Roboto), and placeholder boxes.
  • Strict Rule: No photos, logos, or branded colors. Focus entirely on hierarchy, scale, buttons, and reading order.
  • Design the core 5 to 7 screens required to complete the task you analyzed in Part 1.

Submission Requirements

Please submit the following:

  1. Journey & IA Document (PDF): A combined document containing your visual User Journey Map and Information Architecture diagram.
  2. Figma Link (URL): A link to your Figma file containing your low-fidelity wireframes. (Crucial: Ensure link sharing is set to "Anyone with the link can view").

Grading Rubric (200 Points)

Criteria Excellent (100%) Proficient (80%) Developing (60%) Needs Work (0-50%) Pts
Task Analysis & Journey Deep understanding of user steps, decisions, and friction points. Highly visual. Covers the basic steps but lacks deep insight into user friction. Misses key steps or decisions in the task process. Vague or incomplete journey mapping. 50
Information Architecture Clear, logical hierarchy. Screen structures make perfect cognitive sense. Functional IA, but some structural choices are confusing. Disorganized IA; information is grouped illogically. Missing or incomprehensible IA. 50
Wireframe Structure Excellent layout, hierarchy, and scale. Guides the eye perfectly through the task. Good layout, but some elements lack clear hierarchy or scaling. Poor use of scale, cluttered layout, or confusing navigation. Wireframes fail to support the task. 60
Adherence to Constraints Flawless adherence to grayscale, single-font, structural constraints. Mostly follows constraints, but minor visual styling slipped in. Relied too heavily on visual styling rather than structure. Ignored constraints (used color, images, etc.). 40
