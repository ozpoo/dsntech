Project 02: Building the System

Components, Variables & Design Systems

Canvas Assignment Settings:

  • Points: 200
  • Submission Type: Online
    Website URL / Figma Link + File Upload
  • Allowed File Types: .pdf (for Design System Documentation)

Project Overview

Great interfaces are not built one screen at a time—they are built from systems of reusable parts. Modern product designers rarely create every button, form field, or navigation element independently. Instead, they construct flexible component libraries governed by shared rules, allowing entire products to scale efficiently while remaining visually and functionally consistent.

For this project, introduced during Tuesday Lecture and developed throughout Thursday Labs, you will transform the structural wireframes created in Project 1 into a fully functioning design system. Rather than designing individual screens, you will build the reusable foundation that could generate hundreds of screens through consistent components, variables, and documentation.

Using Figma’s component system, Auto Layout, Variables, and Dev Mode documentation, you will construct a scalable UI library capable of supporting your interaction flow while following accessibility and professional handoff standards.

Pillars Addressed: Systems, Tools, Future-Focused Professional

Course Outcomes: Construct reusable component libraries, implement design tokens and variables, and document scalable design systems for collaborative production.

Learning Objectives

By the end of this project, you will be able to:

  1. Transform interface elements into reusable components and component sets.
  2. Build and organize a scalable design token system using variables for color, typography, spacing, and sizing.
  3. Apply Auto Layout and responsive constraints to create flexible interface components.
  4. Document a professional design system suitable for developer handoff and future expansion.

Lecture vs. Lab Execution Schedule

  • TUE Lecture Briefing: Atomic Design methodology, component architecture, token systems, accessibility standards, design system governance, and developer workflows.
  • THU Lab Execution: Component construction in Figma, Auto Layout implementation, variable creation, variant management, accessibility testing, and documentation for developer handoff.

Step-by-Step Instructions

The Scenario

Continue developing the application you designed in Project 1. Rather than creating additional screens, your task is to build the reusable system that powers those screens.

Imagine your application has grown from a small prototype into a product used by thousands of people. A development team now needs a professional design system that allows them to build new features while maintaining consistency across the interface.

Part 1: Design Tokens & Variables

(Lecture Theory / Lab Construction)

Establish the foundational rules that govern your interface.

Create variables (design tokens) for:

  • Primary, secondary, and semantic colors
  • Typography hierarchy
  • Spacing scale
  • Corner radius values
  • Elevation or shadow styles (if applicable)

Use clear naming conventions that could be understood by another designer or developer.

Part 2: Component Library

(Lab Execution)

Convert the recurring interface elements from Project 1 into reusable components.

Your library should include, at minimum:

  • Buttons
  • Text inputs
  • Navigation elements
  • Cards or containers
  • Icons or icon placeholders
  • Form controls (checkboxes, toggles, radio buttons, etc.)

Each component should be constructed using Auto Layout whenever appropriate.

Part 3: Variants & Component States

(Lab Execution)

Expand your components into interactive systems by creating multiple states.

Examples include:

  • Default
  • Hover
  • Focus
  • Pressed
  • Disabled
  • Error / Success (where appropriate)

Use component properties and variants to minimize duplication and maximize flexibility.

Part 4: Design System Documentation

(Lecture Review / Lab Documentation)

Create a concise documentation page within your Figma file that explains how another designer or developer should use your system.

Include:

  • Naming conventions
  • Token organization
  • Component anatomy
  • Usage guidelines
  • Accessibility considerations
  • Developer notes or specifications

Think of this as the instruction manual for your design system.

Submission Requirements

Please submit the following:

  1. Design System Documentation (PDF): Export a document containing your component inventory, design tokens, naming conventions, and usage guidelines.
  2. Figma Link (URL): A link to your completed Figma file containing your organized component library, variables, variants, and documentation. (Crucial: Ensure link sharing is set to “Anyone with the link can view.”)
