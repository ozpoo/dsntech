Project 01: The Studio Infrastructure

Digital Foundations & Asset System

Canvas Assignment Settings:

  • Points: 150
  • Submission Type: Online
    File Upload + Text Entry
  • Allowed File Types: .pdf, .zip

Project Overview

Before we design, we build the studio. In the physical world, a designer needs a clean desk, organized flat files, and a system for finding their tools. In the digital environment, your operating system (OS), folder structures, and file naming conventions are your studio.

In this project, you will establish the foundational digital infrastructure you will use for the rest of the program. You are shifting from acting as a "student saving homework" to a "future-focused professional managing design assets."

Pillars Addressed: Cognition, Future-Focused Professional

Course Outcomes: Navigate the OS environment, establish file management structures, and implement a reliable cloud/local backup system.

Learning Objectives

By the end of this project, you will be able to:

  1. Design and implement a scalable folder hierarchy for your coursework.
  2. Establish a consistent, professional file-naming convention.
  3. Differentiate between local storage, networked environments, and cloud backups.
  4. Prevent catastrophic data loss through a redundancy strategy.

Lecture vs. Lab Execution Schedule

  • TUE Lecture Briefing: System logic overview, file-naming rules (no spaces, version control, ISO dates), local vs. cloud storage mechanics, and manual documentation standards.
  • THU Lab Execution: Guided setup of folder trees, SSD backup drive configuration, live cloud-sync verification, and instructor pre-flight check of directory links.

Step-by-Step Instructions

Part 1: The Naming Convention

(Lecture Logic / Lab Setup)

Design a standard file-naming convention that you will use for all design files moving forward. It must account for:

  • Project Name or Course Code
  • Version Control (e.g., v01, v02, FINAL)
  • Date (Standardized format like YYYYMMDD)
  • General Rule: No spaces, no special characters (use underscores or dashes)._

Part 2: The Folder Architecture

(Lab Execution)

Create a master folder structure on your local drive for the current academic year.

  • Organize by Semester -> Course -> Projects -> Working Files vs. Final Assets.
  • Create an "Asset Library" folder for global assets (fonts, stock images, textures) that you will use across multiple classes.

Part 3: The Backup Strategy

(Lab Execution)

Set up an automated cloud backup (e.g., Google Drive, Dropbox, or OneDrive) that mirrors your local working directory and connects to your external SSD.

Part 4: The Infrastructure Manual

(Lab Deliverable)

Create a 1-2 page PDF "Studio Manual" documenting your system. This serves as your personal rulebook.

  • Include the formula for your naming convention with three examples.
  • Include screenshots of your Finder/File Explorer showing your new, pristine folder architecture.
  • Include a screenshot showing your folders successfully synced to your cloud storage.

Submission Requirements

Please submit the following:

  1. Your Studio Manual (PDF): The 1-2 page document outlining your naming conventions and featuring your screenshots.
  2. Text Entry Reflection: In the Canvas submission comment box, write a brief paragraph (3-4 sentences) explaining why this strict system is necessary when working collaboratively on a design team.

Grading Rubric (150 Points)

Criteria Excellent (100%) Proficient (80%) Developing (60%) Needs Work (0-50%) Pts
Naming Convention Clear, logical, uses version control/dates, no spaces. System works but lacks one element (e.g., dates). Inconsistent rules or uses spaces/special characters. No clear system developed. 40
Folder Architecture Highly organized, scalable, clearly separates working/final assets. Functional structure but lacks deep organization. Disorganized or shallow structure. Folders are chaotic or missing. 40
Backup Proof Clear evidence (screenshots) of local-to-cloud syncing. Evidence provided, but sync status is unclear. Missing cloud or local proof. No evidence of backup. 40
Professional Reflection Insightful, addresses team collaboration and workflow. Good explanation, but surface-level. Vague understanding of why infrastructure matters. Reflection missing or off-topic. 30
